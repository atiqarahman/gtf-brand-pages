Why This Matters

Every product on GTF flows through this pipeline. If the pipeline is broken, everything downstream breaks:

  • Wrong image selected → wrong attributes extracted → product appears in wrong vibes → customer sees irrelevant results
  • No flat lay generated → no Shop the Look cards → no Outfit Creator compositions → homepage looks empty
  • Bad CSV parsing → wrong prices, missing sizes, duplicate products → customer trust destroyed
  • No image classification → humans manually sort images for every brand → doesn't scale past 10 brands

GTF's entire value proposition — AI-powered discovery, Shop the Look, Outfit Creator, vibe-based matching — depends on clean product data entering the system. This pipeline IS the foundation.

The Complete Pipeline

1

CSV Parsing & Validation ✅

Brand uploads messy CSV/XLSX → fuzzy column mapping → price cleaning → deduplication → size explosion → material normalization → GTF SKU generation

Status: Working. Tested on Bobo (16 products), Afro (59 products), TOD (184→68 deduplicated).

2

Image Acquisition ✅

Download product images from Google Drive (Pattern 3: folder per product, Pattern 4: master folder + SKU match) or store Shopify URLs directly (Pattern 1).

Status: Patterns 3 & 4 working. Pattern 1 (Shopify) untested — ITRH is the first Shopify brand.

3

MediaPipe Image Classification ⚠️ CRITICAL

Classify every image: FULL_BODY / CLOSE_UP / BACK / LIFESTYLE / DETAIL / FLAT_LAY. Select primary (best FULL_BODY) + secondary (best CLOSE_UP/BACK). Route best FULL_BODY to flat lay generator.

Status: Core logic works (95-97% accuracy on test). 4 fixes pending: coverage tiering, CLOSE_UP fallback, primary≠secondary, currency headers. Need to confirm fixes are pushed to repo.

4

v8.1 Attribute Extraction (GPT-4o) ✅

Primary image → hard attributes (category, color, silhouette, length, neckline, sleeve, material, pattern, details). Both images → 11 axis scores + vibe computation. Per-attribute confidence → tiered routing (AUTO/REVIEW/MANUAL).

Status: Working. 260 products extracted. Taste Lab validation in progress. v8.2 prompt guard identified (image beats metadata).

5

Variant C Flat Lay Generation (Gemini) ✅

Takes FULL_BODY image → generates clean transparent-background flat lay of the garment only. Uses SKU category to extract the right piece when model wears multiple items.

Status: Variant C selected as production generator (30/30 benchmark). D-style QA layer to be added post-generation. Nano Banana Pro tested on 6 TOD products — all successful.

6

Shop the Look + Outfit Creator Composition ⚠️

Clean flat lays feed into AI-generated outfit compositions. 3 layers: brand's own sets, cross-brand AI pairings, product + closet basics. Appears on homepage, chatbot, and PDP.

Status: Not built yet. Depends on flat lay generation working at scale. Task 4 in Rahul's wave plan (system design spec).

7

QA / Taste Lab Review ✅

AUTO products → publish. REVIEW products → human quick-check. MANUAL products → full review. Axis Scoring Rubric embedded. Calibration data exported for v8.2 improvements.

Status: Live at gtf-axis-testing.vercel.app. 186 active products. 74 lookbook products paused (source data contamination). Rahul built + shipped 5 tool improvements.

8

Live on Platform 🔴

Products appear on GTF with correct attributes, vibes, flat lay images, Shop the Look cards, and Outfit Creator availability.

Status: Blocked until steps 3 + 6 are complete.

Why MediaPipe Must Be Locked ASAP

🔴 MediaPipe is the single point of failure in the entire pipeline

Every downstream step depends on MediaPipe correctly selecting the right images. If it picks the wrong primary image:

Downstream SystemWhat BreaksCustomer Impact
Attribute ExtractionGPT-4o extracts attributes from wrong image → wrong category, color, silhouetteProduct shows up in wrong vibes, wrong search results
Axis Scoring11-axis scores based on wrong garment → wrong vibe rankingSequin gown ranked as "Old Money", kaftan ranked as "Cool Girl"
Flat Lay GenerationVariant C extracts wrong garment or partial garment from wrong imageShop the Look shows wrong/broken product images
Shop the LookBad flat lays → ugly/incorrect outfit compositionsHomepage looks broken, cross-brand styling fails
Outfit CreatorProducts with wrong images can't be styled together coherentlyCustomer builds outfit with mismatched pieces
Taste LabReviewers validate wrong products → calibration data is noiseModel improvements based on bad data → system gets worse
Brand DashboardBrand sees wrong images for their productsBrand loses trust, leaves platform

⚠️ We already experienced this failure

During axis testing, 74 lookbook products (Surily G + Shahin Mannan) were extracted from the WRONG images due to an image resolver bug. GPT confidently extracted attributes for a completely different garment. A kaftan was classified as a "saree" with 0.95 confidence because the wrong lookbook page was fed in. MediaPipe would have prevented this — it would have classified each page and selected the correct FULL_BODY shot regardless of filename ambiguity.

The Bottom Line

MediaPipe image classification is the foundation. Lock it → attributes are accurate → flat lays are clean → Shop the Look works → Outfit Creator works → vibes are trustworthy → GTF delivers on its promise.

Without reliable image classification, we're building a skyscraper on sand. Every feature we've designed — AI discovery, cross-brand styling, virtual try-on, brand dashboards — assumes the product data entering the system is correct. MediaPipe is what makes it correct.
